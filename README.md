# 舞台吊挂安全放行工作台

本项目用于剧院演出前的吊挂系统安全核验。舞台监督可创建演出批次并登记吊点、吊杆、钢索和连接件；吊挂技师按照系统生成的锁止、磨损、紧固、净空与实测载荷任务录入结果；不合格项会形成分级隐患，整改和针对性复检合格后才能关闭；安全复核人最终冻结不可修改的吊挂清单，并签发带摘要链的开演放行凭据。

服务采用单进程 Go 架构，浏览器页面、同源 JSON API 和 SQLite 持久化由同一个进程提供。SQLite 启用 WAL 与外键，事实写入通过 `expectedVersion` 防止过期覆盖，并通过 `idempotencyKey` 避免重复提交。构件和现场检验支持先预检、后整批原子写入；冻结清单及凭据只追加，页面可重算摘要并显示完整性验证结果。

## 页面操作流程

1. 打开工作台，新建演出核验批次并填写场次资料；也可选择已放行历史批次，逐项裁剪后复制有效构件。新批次始终从独立草拟状态开始。
2. 在“吊挂方案”单项登记或批量粘贴结构化构件行。批量预检会定位重复名称、未知父项和载荷错误；送检前可修订或安全退役，旧版本仍可查询。
3. 在“现场检验”按位置或构件类型筛选任务，单项录入或勾选后批量提交。锁止、实测载荷及所有复检都必须填写证据引用。
4. 对不合格项设置责任人和早于开演的整改截止时间。开放隐患可转派、调期并保留历史；失败复检会留痕并返回待整改，新的整改版本完成后才能进入下一轮复检。
5. 在“复核放行”查看活动构件与修订、载荷、覆盖率、全部隐患结论和阻断原因。先生成十分钟有效的冻结预演令牌，逐项确认后才能冻结并签发放行凭据。
6. 在凭据区可直接按全局序号、完整摘要或摘要前缀检索；系统验证从链首到链尾的序号、前序摘要、内容摘要和关联冻结摘要，并在“审计轨迹”显示事实变更。

## 构建

项目要求 Go 1.24 或更高版本，不需要 Node.js 构建链。

```bash
go build ./cmd/stageclearance
```

## 运行

默认仅监听高位回环地址 `127.0.0.1:19081`，数据写入当前目录的 `stage-clearance.db`：

```bash
go run ./cmd/stageclearance
```

可显式指定回环监听地址和数据库路径：

```bash
go run ./cmd/stageclearance -addr=127.0.0.1:19444 -db=./var/stage-clearance.db
```

也可以设置 `PORT` 为端口号；未传 `-addr` 时会绑定 `127.0.0.1:<PORT>`。服务拒绝非回环监听地址。浏览器访问对应地址即可进入工作台。

## 测试与自检

运行全部自动化测试：

```bash
go test ./...
```

运行有界业务冒烟。`-selfcheck` 会在指定的真实 HTTP 地址启动服务，以 HTTP 客户端依次完成批次创建、构件登记、五项检验、阻断隐患生成、整改、复检、冻结、凭据签发与完整性验证，然后优雅关闭并自行退出；默认数据库参数下使用内存 SQLite，不污染业务数据。

```bash
go run ./cmd/stageclearance -addr=127.0.0.1:19081 -selfcheck
```

正常服务收到 `SIGINT` 或 `SIGTERM` 后会在限定时间内完成优雅关闭。
